# Controller Preflight — execution-start boundary

Controller preflight is an INIT observation once per cycle, not a separate CI job required before every file mutation. Use `.github/workflows/controller_preflight.yml` for the optional remote execution interface and reuse `libs/command_execution/preflight.py` in the future Orchestrator. No new required CI dependency/architecture check.

The startup request binds repository, work ID, cycle ID, trusted Controller revision, target branch and target revision. The observation checks current main/target identity only. It does not fetch or validate the Samuel central contract; the receipt explicitly records central_contracts_checked=false. This is an ownership change, not a clearance of the previous HTTP 403. Existing central contract validation in Repository CI, central skill initialization where required by the active OS, and operation-specific mutation authority remain unchanged. It does not authenticate work enrollment, checkpoint history, blocker clearance, runtime transport availability, or execution permission. Those remaining INIT obligations belong to the Controller/Orchestrator. Missing evidence stays unresolved; a startup receipt alone is not permission to mutate. Prior same-work denials, canonical branch preflight, and fresh per-operation target checks remain governed by the existing mutation owner. The existing connector policy probe is retained as a separately invoked explicit operation diagnostic, not the Controller startup workflow.
