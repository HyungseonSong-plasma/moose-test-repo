# Purpose-routed GitHub Actions workflows

The checked-in `.github/workflows/ci.yml` is static GitHub Actions YAML, not
generated while a workflow runs. Its authoritative template is
`ci/workflow_templates/general-ci.yml`.

## Repository Integration Contract Verification (v0.1)

The authoritative contract is [Repository Integration Contract Verification](REPOSITORY_INTEGRATION_CONTRACT.md).
General `Repository CI` contains only unconditional `validate`, verifying shared
integration contracts at the exact PR HEAD or main push. It has no
`paths-ignore` filter. `physics-code-ci.yml` owns Physics/FDEG source tests,
`physics-native-ci.yml` owns expensive P1/P2 Native checks, and
`repository-diagnostics.yml` is manual-only. There must be no
PR-number-specific experiment jobs in Repository CI.
`python3 ci/workflow_harness.py --check` checks deterministic generated bytes
and `ci/guards/repository_ci_scope.py --check` checks ownership and skips.

## Special-purpose CI (explicit activation)

`ci/workflow_profiles.json` contains an allowlisted special experiment route,
its reviewed job-only YAML template, target issue and generated output pathname.

The Issue #493 P3 profile is initially `"activation": "deferred"`, so ordinary
PRs and main pushes do **not** launch another expensive four-arm P3 run.
The workflow template remains versioned and testable; its generated workflow
file is **intentionally absent**. A deferred output unexpectedly present in
`.github/workflows/` is a CI failure.

Only upon a *separate* decision to run that experiment again:

1. Confirm no duplicate active Native solver run; validate scientific and
   execution authorization, reviewed exact source pins, immutable OCI and
   sanitized data boundaries.
2. Change only the selected manifest profile's `activation` from `deferred`
   to `active`.
3. Run `python3 ci/workflow_harness.py --generate` in the proposed branch,
   inspect the generated `issue493-public-p3-once.yml`, run `--check`, and
   open a PR for review. Do not commit any private rate input or raw results.
4. Following approval and merge to `main`, the pre-existing
   `workflow_surface_guard.py` permits **one self-path-triggered main push
   execution**, not a catch-all PR action.
5. After the one-shot run has finished and evidence is preserved, return the
   profile to `deferred` and remove the generated file in a separately
   reviewed cleanup change. This cleanup must not launch the experiment.

Routes for unregistered purposes or issue numbers fail closed; no automatic
task inference, PR-number fallback, workflow dispatch, ruleset modification,
or secret-bearing execution is part of the generator.

The common `Repository CI` gate and `SOL Runtime Integration` workflow
remain governed independently. The core `validate` Job is now unconditional
on its accepted events, including PR metadata edits, so an entirely skipped
required integration gate cannot produce a misleading successful Workflow.

## B-only 600-second diagnostic (separate one-shot profile)

The `issue493-public-p3-diagnostic` profile is a distinct **special** route
selected by `--route special --issue 493 --variant diagnostic`. It does not
replace the existing `--variant full` route, which remains `deferred`.
A reviewed one-shot `issue493-public-p3-diagnostic-once.yml` is generated
from the job-only template and triggers **only on its own path on main push**.
Its two case lanes run B with the full original 460-step input for exactly
600 seconds maximum each; C is forbidden. Diagnostic timeout is evidence,
not successful P3 completion; the job validates `P3=HOLD`, `P4=NOT_RUN`,
`SCIENCE_HOLD` and only publishes sanitized JSON/heartbeats and P1 proof.
After collection, move this profile back to `deferred` and delete the one-shot
file in a separate cleanup PR; the full profile stays deferred throughout.

reserving 20 minutes for immutable-source checkout, P0/P1/P2, and artifact

non-empty Exodus and 0–100µs time coverage before marking B completion
PASS. A timeout is recorded with `P3=HOLD`, reported via sanitized
status/artifact, and makes the job fail (not synthetic PASS).
The overall B/C P3 stays HOLD and P4 NOT_RUN even if B finishes, until a
separate C solve and quantitative comparison are completed.
After this one-shot, remove/defer its YAML and profile in a separate
governed cleanup; no unreviewed workflow_dispatch or duplicate runner.

## Public B/C raw-output archive and P4 follow-up (2026-11-10)

The user explicitly requested downloadable Exodus/CSV after #506 finished B
successfully but published only its sanitized JSON evidence. Previous ephemeral
runner-local raw output was lost; it cannot be restored from the small
artifacts. This one-shot therefore runs fresh public-rate B then C, in two
successive case-matrix jobs (max two concurrent cases), to respect the 6-hour
GitHub-hosted per-job limit. Each single-arm solver has at most 20,400 seconds.
All historical source, mesh, candidate, 19 public Boltzmann tables, model
settings and 460-step 0-100us grid are pinned and unchanged.

The B-native PhysicsApp ELF and exact P1 record are transferred as a separately
verified SHA-bound artifact to C; each C re-verifies Git source, pinned OCI,
ELF SHA, P1 identity and P2 before launching on the SAME binary as B in its
case. On each successful 461-frame output, only plasma.e, plasma.csv and a
SHA/identity manifest are copied into new public-only 90-day GitHub
downloadable artifacts. Raw solver logs, staged inputs, unreviewed rate
data and original private-rate tables are never uploaded.

An automatic P4 job independently rehashes all four results, requires same
mesh and binary per B/C case, compares 461 CSV timestamps/fields, and computes
numerical differences for all Exodus field arrays, publishing metrics JSON
and case time-trace PNG files in a separate 90-day artifact. These metrics
DO NOT establish scientific equivalence absent agreed tolerances; the original
protected-rate A/A-prime controls remain separate, SCIENCE_HOLD persists.

The prior B-only completion workflow is removed and its profile set to
deferred, so it cannot be retriggered by the new merge. The old full four-arm
profile also remains deferred. Retire this one-shot via a future cleanup
after results are preserved.
