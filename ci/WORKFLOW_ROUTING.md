# Purpose-routed GitHub Actions workflows

The checked-in `.github/workflows/ci.yml` is static GitHub Actions YAML, not
generated while a workflow runs. Its authoritative template is
`ci/workflow_templates/general-ci.yml`.

## General CI

General CI retains all mandatory checks and the original `push`/`pull_request`
trigger contract. There must be no PR-number-specific jobs in general CI.
`python3 ci/workflow_harness.py --check` compares generated bytes to committed
outputs, and `--self-test` tests positive/negative routing cases.

## Special-purpose CI (explicit activation)

`ci/workflow_profiles.json` contains an allowlisted special experiment route,
its reviewed job-only YAML template, target issue and generated output pathname.

The Issue #493 P3 profile is initially `"activation": "deferred"`, so ordinary
PRs and main pushes do **not** launch another expensive four-arm P3 run.
The workflow template remains versioned and testable; its generated workflow
file is **intentionally absent**. A deferred output unexpectedly present in
`.github/workflows/` is a CI failure.

Only upon a *separate* decision to run that experiment again:

1. Confirm no duplicate active Native solver run; validate scientific and
   execution authorization, reviewed exact source pins, immutable OCI and
   sanitized data boundaries.
2. Change only the selected manifest profile's `activation` from `deferred`
   to `active`.
3. Run `python3 ci/workflow_harness.py --generate` in the proposed branch,
   inspect the generated `issue493-public-p3-once.yml`, run `--check`, and
   open a PR for review. Do not commit any private rate input or raw results.
4. Following approval and merge to `main`, the pre-existing
   `workflow_surface_guard.py` permits **one self-path-triggered main push
   execution**, not a catch-all PR action.
5. After the one-shot run has finished and evidence is preserved, return the
   profile to `deferred` and remove the generated file in a separately
   reviewed cleanup change. This cleanup must not launch the experiment.

Routes for unregistered purposes or issue numbers fail closed; no automatic
task inference, PR-number fallback, workflow dispatch, ruleset modification,
or secret-bearing execution is part of the generator.

The common `Repository CI` gate and the `SOL Runtime Integration` workflow
remain governed independently. A GitHub Actions `edited` event intentionally
filtered by required CI jobs may still yield skipped checks; eliminating
**unrelated experiment job skips** does not imply zero skips on every event.
